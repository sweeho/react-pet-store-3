### SWHR3-R-0015 · Database lock contention tolerance

#### SWHR3-R-0015.01 · Admin order queue loads while another process is writing
- **SWHR3-C-0036** (e2e, approved, v1) Admin order queue answers 200 while another process holds a write lock
  - Preconditions: Dev server running on the E2E port against the file-backed sqlite.db; a registered account promoted to admin via the grant-admin script; at least one order seeded for it.
  - Step 1: Sign in as the administrator.
  - Step 2: Spawn a separate Bun process that opens sqlite.db, runs BEGIN IMMEDIATE, inserts a row, sleeps about 1 second, then commits.
  - Step 3: While that process holds the lock, request GET /api/admin/orders with the admin session.
  - Step 4: Wait for the holder process to exit.
  - Expected: GET /api/admin/orders answers 200 with the orders grouped by status, including the seeded order; the response body never contains "database is locked" and the status is never 500.

#### SWHR3-R-0015.02 · A write request waits for a concurrent writer
- **SWHR3-C-0037** (e2e, approved, v1) Registration made during a concurrent write transaction succeeds
  - Preconditions: Dev server running on the E2E port against the file-backed sqlite.db.
  - Step 1: Spawn a separate Bun process that opens sqlite.db, runs BEGIN IMMEDIATE, inserts a row, sleeps about 1 second, then commits.
  - Step 2: While that process holds the lock, POST /api/auth/register with a unique user name and matching passwords.
  - Step 3: Wait for the holder process to exit, then sign in with the new credentials.
  - Expected: The registration answers a success status (not 500) after the lock is released, and signing in with the new account succeeds.
- **SWHR3-C-0038** (integration, approved, v1) A write on an openDatabase connection waits for another process's write lock and succeeds
  - Preconditions: A temporary database file with one table, opened through openDatabase(file) from db/client.ts.
  - Step 1: Spawn a child Bun process that opens the same temp file, runs BEGIN IMMEDIATE, inserts a row, holds the lock for about 1 second, then commits.
  - Step 2: Once the child reports it holds the lock, insert a row through the openDatabase connection and time it.
  - Step 3: Count the rows in the table.
  - Expected: The insert does not throw; it completes after roughly the child's hold time (well above 0 ms, under 5 s), and both rows are present.

#### SWHR3-R-0015.03 · Operator scripts run concurrently with the server
- **SWHR3-C-0039** (e2e, approved, v1) Order-approval spec passes repeated four times with no retries
  - Preconditions: e2e/order-approval.spec.ts contains no retries override; the spec spawns grant-admin and seed-orders scripts in parallel workers against the dev server's sqlite.db.
  - Step 1: Run e2e/order-approval.spec.ts fully parallel, repeated four times, with retries set to 0.
  - Expected: Every test in every repetition passes on its first attempt; no test fails with a 500 or "database is locked" error, and no operator script exits non-zero.
- **SWHR3-C-0040** (e2e, approved, v1) Several operator scripts started at once alongside server requests all succeed
  - Preconditions: Dev server running against the file-backed sqlite.db; five freshly registered accounts.
  - Step 1: Start the grant-admin script for all five accounts and the seed-orders script (count 5) for each at the same moment, without the E2E retry helper.
  - Step 2: While they run, issue ten concurrent GET /api/session and GET /api/admin/orders requests with an admin session.
  - Step 3: Wait for every script to exit.
  - Expected: Every script exits with status 0 and prints its success output; every server request answers a non-500 status and none returns "database is locked".

#### SWHR3-R-0015.04 · A lock that is never released still fails
- **SWHR3-C-0041** (unit, approved, v1) openDatabase connections carry a 5000 ms busy timeout, file and in-memory
  - Preconditions: openDatabase is exported from db/client.ts; a temporary file path is available.
  - Step 1: Open a connection with openDatabase(tempFile) and read PRAGMA busy_timeout, PRAGMA journal_mode and PRAGMA foreign_keys.
  - Step 2: Open a connection with openDatabase(":memory:") and read PRAGMA busy_timeout.
  - Step 3: Close both and delete the temp file and its -wal/-shm sidecars.
  - Expected: The file connection reports busy_timeout 5000, journal_mode wal and foreign_keys 1; the in-memory connection reports busy_timeout 5000.
- **SWHR3-C-0042** (integration, approved, v1) A write blocked by a lock held longer than 5 s fails after about 5 s
  - Preconditions: A temporary database file with one table, opened through openDatabase(file).
  - Step 1: Spawn a child Bun process that opens the same file, runs BEGIN IMMEDIATE, and holds the lock for about 8 seconds.
  - Step 2: Once the child reports it holds the lock, attempt an insert through the openDatabase connection and time it.
  - Step 3: Terminate the child and clean up the temp file.
  - Expected: The insert throws a "database is locked" error after between about 4.5 and 6.5 seconds, not immediately and not after the child releases the lock.
