## order-checkout

### SWHR3-R-0049 · Order submission accepts only JSON

#### SWHR3-R-0049.01 · Form-encoded submission is refused
- **SWHR3-C-0146** (integration, approved, v1) Form-encoded checkout is refused with 415 and writes nothing
  - Preconditions: Signed-in customer session cookie; a cart cookie whose cart holds two items; a complete checkout field set (_a, _b and card fields).
  - Step 1: Through middleware/auth.ts and middleware/cart-session.ts, send POST /api/orders with content-type application/x-www-form-urlencoded and the fields URL-encoded.
  - Step 2: Count orders rows and read the cart.
  - Expected: The handler throws a 415 with data.code UNSUPPORTED_MEDIA_TYPE; the orders count is unchanged; the cart still holds both items.
- **SWHR3-C-0147** (unit, approved, v1) readJsonBody refuses application/x-www-form-urlencoded
  - Preconditions: An H3Event for POST with content-type application/x-www-form-urlencoded and body a=1.
  - Step 1: Call readJsonBody(event).
  - Expected: It rejects with UnsupportedMediaTypeError, which toHttpError maps to 415 with code UNSUPPORTED_MEDIA_TYPE and message "Request body must be JSON".

#### SWHR3-R-0049.02 · Plain-text submission is refused
- **SWHR3-C-0148** (integration, approved, v1) text/plain checkout carrying JSON is refused
  - Preconditions: Signed-in customer with a two-item cart; a complete checkout body serialised as JSON text.
  - Step 1: Send POST /api/orders with content-type text/plain and the JSON text as body.
  - Step 2: Count orders rows and read the cart.
  - Expected: The response is 415; no order is added; the cart still holds both items.

#### SWHR3-R-0049.03 · Multipart submission is refused
- **SWHR3-C-0149** (integration, approved, v1) Multipart checkout is refused with 415, not a parser 400
  - Preconditions: Signed-in customer with a two-item cart; a complete checkout field set as FormData.
  - Step 1: Send POST /api/orders with the FormData body (content-type multipart/form-data with boundary).
  - Step 2: Count orders rows and read the cart.
  - Expected: The response is 415 with code UNSUPPORTED_MEDIA_TYPE (not 400 "Invalid JSON body"); no order is added; the cart is unchanged.

#### SWHR3-R-0049.04 · Submission without a content type is refused
- **SWHR3-C-0150** (integration, approved, v1) Checkout with no content-type header is refused
  - Preconditions: Signed-in customer with a two-item cart; a complete checkout body serialised as JSON text.
  - Step 1: Send POST /api/orders with the JSON text and no content-type header.
  - Step 2: Count orders rows and read the cart.
  - Expected: The response is 415; no order is added; the cart still holds both items.
- **SWHR3-C-0151** (unit, approved, v1) readJsonBody media-type table
  - Preconditions: H3Events with a JSON body and each content-type header in turn.
  - Step 1: Call readJsonBody for: application/json; application/json; charset=utf-8; Application/JSON; (no header); text/plain; multipart/form-data; application/jsonp.
  - Expected: The first three resolve to the parsed body; the last five reject with UnsupportedMediaTypeError.

#### SWHR3-R-0049.05 · JSON submission with a charset parameter is accepted
- **SWHR3-C-0152** (integration, approved, v1) JSON checkout with a charset parameter places the order
  - Preconditions: Signed-in customer with a two-item cart; a complete checkout body.
  - Step 1: Send POST /api/orders with content-type application/json; charset=utf-8 and the JSON body.
  - Expected: The response is 201 with orderId, orderDate and email; one order is added and the cart is empty.
- **SWHR3-C-0153** (e2e, approved, v1) Browser checkout still succeeds end to end
  - Preconditions: Catalogue seeded; a signed-in customer with a profile and a populated cart.
  - Step 1: Visit /checkout, fill shipping and payment, click "Place order".
  - Expected: The browser lands on /orders/<id> showing the order confirmation.

#### SWHR3-R-0049.06 · Refused submission records no order log entry
- **SWHR3-C-0154** (integration, approved, v1) A refused submission writes no checkout log line
  - Preconditions: Signed-in customer with a two-item cart; console.info spied on.
  - Step 1: Send POST /api/orders with content-type text/plain and a complete JSON body.
  - Step 2: Send it again with application/x-www-form-urlencoded.
  - Expected: Both answer 415, and console.info was never called with a message starting "checkout: order".
- **SWHR3-C-0155** (integration, approved, v1) A signed-out non-JSON submission answers 401 and logs nothing
  - Preconditions: No session cookie; a cart cookie with items; console.info spied on.
  - Step 1: Send POST /api/orders with content-type text/plain and a complete JSON body.
  - Expected: The response is 401 (authentication is checked first); no order is added; no "checkout: order" log line is written.
