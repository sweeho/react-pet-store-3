## order-checkout

### SWHR3-R-0036 · Billing address collection

#### SWHR3-R-0036.01 · All required billing address fields are collected
- **SWHR3-C-0098** (unit, approved, v1) A complete billing address is accepted with every field
  - Preconditions: Fields: family_name_a "Chen", given_name_a "Sarah", address_1_a "1247 Larkspur Avenue", city_a "Palo Alto", state_or_province_a "CA", postal_code_a "94301", country_a "United States", telephone_number_a "+1 650 555 0134", email_a "sarah.chen@example.com"; a new FieldErrorCollector.
  - Step 1: Call extractContactInfo(fields, "_a", errors).
  - Expected: It returns a ContactInfo with familyName "Chen", givenName "Sarah", address1, city, stateOrProvince "CA", postalCode "94301", country, telephoneNumber and email as given, and the collector records nothing.
- **SWHR3-C-0099** (integration, approved, v1) The billing section offers every address field
  - Preconditions: Signed-in customer; the cart holds one item; the profile fetch answers 404 (no pre-fill).
  - Step 1: Render the /checkout page and wait for the form.
  - Expected: Section "Billing address" has labelled inputs Given name, Family name, Address line 1, Address line 2 (marked Optional), City, State or province, Postal code, Country, Telephone and Email, named given_name_a, family_name_a, address_1_a, address_2_a, city_a, state_or_province_a, postal_code_a, country_a, telephone_number_a, email_a.

#### SWHR3-R-0036.02 · Address line 2 is optional
- **SWHR3-C-0100** (unit, approved, v1) A blank address line 2 is stored as null
  - Preconditions: A full billing field set with address_2_a absent, and a second set with address_2_a "   ".
  - Step 1: Call extractContactInfo on each set with suffix "_a".
  - Expected: Both return a ContactInfo with address2 === null, and the collector records no error for address_2_a.
- **SWHR3-C-0101** (integration, approved, v1) An order without address line 2 is placed and stores null
  - Preconditions: Signed-in customer with a populated cart; a full valid checkout body with no address_2_a or address_2_b.
  - Step 1: Send POST /api/orders with the body.
  - Step 2: Read the order's order_contacts rows.
  - Expected: The response is 201, and both BILL_TO and SHIP_TO rows have address_2 NULL.

#### SWHR3-R-0036.03 · Required billing fields are validated
- **SWHR3-C-0102** (integration, approved, v1) Missing billing fields are listed on the checkout page
  - Preconditions: Signed-in customer with a populated cart; orders-api placeOrder mocked to reject with a 422 ApiError: missingFields ["city_a", "postal_code_a"], fieldErrors {city_a: "Enter a city.", postal_code_a: "Spaces only — enter a code."}.
  - Step 1: Render /checkout, type a value into given_name_a, and click "Place order".
  - Expected: An alert reads "Your order was not placed — 2 required fields are missing" and lists "Billing · City" and "Billing · Postal code"; "Enter a city." appears beside City; the typed given name is still in its input.
- **SWHR3-C-0103** (integration, approved, v1) POST /api/orders with a missing billing field answers 422 and creates nothing
  - Preconditions: Signed-in customer with a populated cart; a full valid body with city_a set to "".
  - Step 1: Send POST /api/orders with the body.
  - Step 2: Count orders rows.
  - Expected: The response is 422 with code VALIDATION_FAILED, data.missingFields ["city_a"] and data.fieldErrors.city_a set; no orders row was added and the cart is unchanged.

### SWHR3-R-0037 · Shipping address collection

### SWHR3-R-0047 · Transactional order creation

#### SWHR3-R-0047.01 · Order creation is transactional
- **SWHR3-C-0139** (unit, approved, v1) placeOrder joins an outer transaction
  - Preconditions: A populated cart; db.transaction is spied on.

  - Expected: db.transaction is called exactly once (the outer call), and after commit the order exists.

#### SWHR3-R-0047.02 · Partial failures rollback entire order

  - Step 2: Count orders and order_contacts rows and read the cart.
